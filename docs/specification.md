## 3. ゲーム概要

ブラウザで遊ぶ、和風の3D漢字バトルゲーム。

ガチャで引いた漢字を採用または破棄し、採用順に4文字を作る。実在の四字熟語である必要はなく、自由な造語でよい。4文字そのものを立体化し、一体のモデルとして戦わせる。文字から生き物を生成する仕様ではない。

勝敗はポイントの合計で決まる。3Dはポイント加算と勝敗を表現するための演出であり、アクション操作や物理衝突による勝敗判定は不要。

## 4. 画面遷移

```text
ホーム → ガチャ → 試合 → リザルト
   ↕                        ├→ もう一度書く → ガチャ
 漢字一覧                   └→ ホーム
```

### ホーム

- ゲーム開始用ボタン。文言は未確定。
- ［漢字一覧］ボタン。

### 漢字一覧

- ガチャに出る全250字を、7グループ別に閲覧できる。
- 未取得の漢字も最初から表示する方針。
- ［ホーム］で戻る。
- 補填専用の数字「1」はガチャ対象ではなく、この250字に含めない。

### ガチャ

1. ［引く］を押す。
2. ガチャのアニメーションが流れる。
3. 抽選された漢字と［書く］［消す］を表示する。
4. ［書く］なら取得、［消す］なら破棄。
5. 続行条件を満たしていれば次の［引く］へ進む。

- 抽選は最大10回。書く・消すのどちらでも1回分の抽選を消費する。
- 4文字を取得した時点で即終了。残りの抽選は行わない。
- 取得した順に左から並ぶ。風→林→火→山なら「風林火山」。並べ替え機能は要求されていない。
- 同じ漢字が複数回出てもよく、重複取得も可能。
- 残り抽選回数と取得済みの文字を表示する方針。
- 10回目の漢字の採否を決めた後、4文字に届かなければ不足分を数字「1」で右側に補填する。

### 数字「1」の最優先ルール

- 補填されるのは漢数字の「一」ではなく、数字の「1」。
- 「1」が1つでも含まれれば、その4文字全体の最終合計点は必ず1点。
- 他の漢字、組み合わせ、レアリティの点数がどれだけ高くても、このルールを優先する。
- 「風林火1」「風111」「1111」はすべて全体で1点。
- 通常の漢数字「一」はガチャ対象の漢字であり、この特例を適用しない。
- 実装では補填文字と通常漢字を型または明確な識別子で区別する。

### 試合

- 敵は収録漢字からランダムに4文字を選ぶ。重複あり。ガチャの採否選択や補填はしない。
- 敵にもプレイヤーと同じ通常の得点計算を適用する。
- 配置：敵の4文字とポイントを左上、自分の4文字とポイントを右下。
- 4文字は一体となって浮遊する3Dモデル。
- 以下の順番で表示と加点を行う。
  1. 左から各漢字の文字ポイント。「風のポイント ＋○点」のように表示。
  2. 組み合わせポイント。
  3. レアリティポイント。
- 合計表示が加点ごとに増え、モデルが揺れるなどの演出を行う。
- 合計点が高い側が勝ち。同点は引き分け。
- 決着時、勝者が相手を吹き飛ばす演出。演出終了後にリザルトへ自動遷移。
- 引き分けの具体的な演出は未確定。
- 数字「1」を含む場合の途中表示方法は未確定。最終合計が必ず1点になること、例外を画面上で理解できることを守る。

### リザルト

- 四字熟語と点数を表示する。
- ［もう一度書く］でガチャからやり直す。
- ［ホーム］でホームへ戻る。
- 最後にコメントを表示する。通常コメントは複数用意する。文面は開発側で初期案を用意できる。
- 自分の4文字に数字「1」が含まれる場合、コメントは必ず「もはや漢字じゃない」。他のコメント条件より優先する。
- 敵の最終点や内訳など、結果画面に追加で表示する詳細は未確定。

## 5. 得点とデータ管理

通常の合計点は次の3要素の合計。

1. 4文字それぞれの文字ポイント
2. 文字の組み合わせによる熟語ポイント（組み合わせポイント）
3. 4文字それぞれのレアリティポイント

### 確定している制約

- バトルごとに抽選し直す。
- レアリティ自体もバトルごとにランダム。文字に固定しない。
- 乱数やベクトルを数百文字分個別設定すると調整が難しいため、グループ単位で管理する。
- 漢字の分類は必ず7グループ。8グループ以上には増やさない。
- 各漢字は1つのグループに所属する。
- 漢字個別の基本データは文字と所属グループ。文字ポイントの乱数範囲と属性ベクトルは所属グループから取得する。
- 同じグループの文字でも、文字ポイントは1文字ずつ独立して抽選する方針。
- レアリティの抽選表は共通設定で管理する方針。

### 組み合わせポイント：提案段階の設計

ユーザーはベクトルの内積の使用を提案している。会話では以下の方式を提案したが、詳細な式・数値はまだ確定していない。

- 各グループに固定の属性ベクトルを持たせる。
- 4文字の全6ペアで内積を計算し、合計を相性値とする。
- 相性値にバトルごとの乱数倍率を掛けて組み合わせポイントにする。
- 同じグループだけで常に最善になるか、グループ間の関係も選択肢になるかを確認して初期設定する。

ベクトルの次元、正規化、丸め、倍率、上限、重複ペアの扱いは初期実装で明文化する。グループが7つであることと、ベクトルが7次元であることは別であり、次元数は未確定。

### レアリティ

| レアリティ | 演出色 |
|---|---|
| N | 白 |
| C | 緑 |
| R | 銅色 |
| SR | 金 |
| UR | 虹色 |

各文字のレアリティポイント加算時に対応色で演出する方針。ガチャ時点の色をレアリティ確定表示にすると「バトルごとに抽選」と矛盾するため、ガチャ演出の色と区別する。

- レアリティの確率と点数、点数を固定値にするか範囲抽選にするか。
- 漢字のガチャ排出確率。初期案は250字の均等抽選にできる。

## 13. ルール実装と仮の初期設定（区切り3）

以下の点数・確率・相性方式の詳細は開発側が用意した初期設定であり、ユーザーが確定した数値ではない。

- ガチャと敵は250字から均等抽選し、復元抽選（同じ字の再登場・重複取得あり）とする。
- 全7グループの文字点は10〜100の整数、両端を含む。4文字それぞれ独立抽選する。
- 属性ベクトルは3次元で、計算時に長さ1に正規化する。ゼロベクトルは不可。具体値は `src/data/groups.ts` に集約。
- 組み合わせ点は4文字の位置に基づく全6ペアの正規化内積の合計 × 20 × 試合ごとの乱数倍率。倍率は0.8以上1.2未満の一様抽選。最後に四捨五入し、0〜160点へ制限する。重複した字やグループのペアも位置ごとに数える。
- この正規化内積方式では、同一グループ4字の相性値6が最大となる。混成で必ず有利になる仕組みではない。各字のランダム得点とレアリティを含む最終勝敗は別途決まる。相性設計は今後調整可能。
- レアリティは各文字独立の共通抽選。N／C／R／SR／URの重みは50／28／15／6／1（合計100）、固定加算点は0／10／30／80／200。文字には固定しない。
- 通常の加点手順は、左から文字点4件→組み合わせ点1件→左からレアリティ点4件。
- 補填文字は `kind: 'filler'`、通常漢字は `kind: 'kanji'` で区別する。補填が1つでもあれば通常得点の抽選・加算を行わず、理由を付けた合計1点の特例データを返す。通常の漢数字「一」は対象外。
- `createBattle` は敵の4字、双方の得点・手順、勝敗、結果コメントを一度に確定する。画面側は返された結果を保持し、演出時に再抽選しない。敵は補填なしで同じ通常得点関数を使用する。
- ガチャ状態は操作ごとに新しい値を返す。10回目は採否の決定後に右側へ補填し、4字取得時は直ちに終了。再戦は `createGacha` から新規作成する。
- `npm test` でデータ整合性、ガチャ境界、全15種類の補填位置パターン、得点・レアリティ境界、加点順序、勝敗・新規試合を検証する。画面・タイマー・3D演出の再戦時リセットは該当画面の実装時に確認する。

## 17. ユーザー確定の改訂：レアリティ保持とターン制バトル

### 確定したルール

- ガチャで文字とレアリティを抽選し、N／C／R／SR／URの名前と色を表示する。採用文字にはレアリティを保持し、試合では再抽選しない。敵も文字とレアリティを一度だけ抽選する。
- 通常の合計点は100〜99,999点。補填数字「1」があれば合計1点の最優先ルールを維持する。
- 得点比較での勝敗判定を廃止し、合計点を能力の総量、7グループの構成を体力・攻撃力・防御力への配分に使う。
- 配分と能力別係数の後、双方の各能力に独立した1.0〜2.0倍の乱数を掛けて四捨五入する。能力は試合開始時に一度だけ確定し、試合中に再抽選しない。
- 数字「1」を含む側は乱数倍率を使わず、最終体力・攻撃力・防御力をすべて1とする。
- 先攻はランダム。その後は交互に自動攻撃する。ダメージは `攻撃力 × 攻撃力 ÷ (攻撃力 + 相手の防御力)` を四捨五入し、最低1。体力は0未満にならず、0になったら即終了する。
- 加点時は対象文字付近から「＋点数」が出て総ポイント欄へ飛び、到着時に加算・欄を発光させる。組み合わせ点は4文字の中央から出る。補填側は最初から1点で加点移動を行わない。
- 得点集計完了後に能力値を表示し、ターン制バトルを始める。4文字が一体で接近し、命中で火花・輪状衝撃波・打撃音・ダメージ表示・HPバー更新。元に戻って次のターン。決着時は敗者を吹き飛ばし、リザルトへ自動遷移する。
- 試合にはHPバーと「体力:現在値/最大値」（緑）、「攻撃力:数値」（赤）、「防御力:数値」（青）。リザルトにも双方の4文字・ポイント・終了時体力/最大体力・攻撃力・防御力を表示する。
- 勝利・敗北・引き分けで別々のコメント群を用意する。補填時はどの勝敗でも「もはや漢字じゃない」を最優先する。
- 効果音は切り替え可能とし、再戦・ホーム復帰時に古い描画・飛行ポイント・音・待機処理が残らないようにする。

### 開発側が用意した調整可能な初期設定

- 文字点は全グループ25〜12,000、組み合わせ点は6ペアの正規化内積合計 × 2,800 × 0.8〜1.2未満の乱数、四捨五入して0〜19,999へ制限。
- レアリティ確率は50／28／15／6／1のまま。加点はN:0、C:500、R:2,000、SR:4,000、UR:8,000。
- 通常点の最小100・最大99,999を保つ。設定変更で範囲を超えた場合も最終調整の加点手順を追加し、表示の累積と最終点を一致させる。
- グループ別配分（体力／攻撃力／防御力）：天象・光30/50/20、地象・物質35/15/50、草木55/15/30、生物・身体45/35/20、心情・知性25/25/50、行動・武芸20/60/20、性質・数量34/33/33。4文字分の配分を等重みで平均する。
- 能力係数は体力8、攻撃力2、防御力1.6。乱数倍率は0.001刻みで1.000〜2.000を両端含めて抽選する。
- 200ターンで双方が生き残った場合は長時間化防止のため引き分けにする。上限は `src/data/combat.ts` に集約する。
- 攻撃演出は接近260ms、命中後540ms。ポイント移動600ms、到着後420ms。動きを減らす設定では飛行の代わりに短いフェードを使い、突進・火花・衝撃波は省略する。

- 白いNの文字も背景に埋もれないよう、文字輪郭に細い線を付ける。

- 方位はプレイヤーの現在座標から即座に決定し、中心を越えたら反対側へ瞬間的に切り替える。角度の補間・角速度制限・中心付近の不感帯は廃止。
- 座標が中心と完全に一致した瞬間だけ、方位を定義できないため直前の向きを保持する。
- 後方距離6・文字より上3、縦画面の距離補正は維持。注視点は常に中心の高さ1。ポイント集計中は全景。
- カメラ方位に合わせた移動入力、Y軸回避、移動速度5は維持する。


## 22. 中心切り替えの滑らかな追従を復元

- 「中心 → プレイヤー → カメラ」の配置を目標とし、注視点は常に中心の高さ1を維持。切り替え中は角度を補間して目標配置へ追従する。
- 第21節の瞬間反転を廃止し、最短角度差による滑らかな回転と中心半径1.4の不感帯を復元。
- 最大角速度は旧1.6から6rad/秒、追従係数は旧4から12へ増加。動きを減らす設定では最大角速度を半分にする。
- 移動入力と回避方向の変換には、補間中の配置角ではなく実際のカメラから中心を見る方位を使用する。
- 後方距離6・文字より上3・縦画面補正、移動速度5、Y軸回避は継続。

## 23. Enterキーで試合開始

- 集計と能力表示が完了した準備完了状態で、Enterキー（テンキー含む）または戦闘開始ボタンで開始できる。
- Enter長押し・戦闘開始後の再入力では開始処理を繰り返さない。Escで一時停止／再開する。
- ホームなど別のボタン・リンクのEnter操作、入力欄、IME変換中の操作は妨げない。画面離脱時にリスナーを解除する。

## 24. 方向別回避・操作表示・戦闘エフェクト

- 回避開始時のカメラ方位で移動方向を前後・左右へ分解する。前後優勢は画面横方向のX軸、左右優勢はワールドY軸の1回転。斜め同量はX軸。静止回避も実際の退避方向で判定する。
- 回避開始時の軸・符号・方位を保存し、回避中にカメラが周回しても軸を切り替えない。終了後は通常の向きへ戻す。
- プレイヤーの漢字上へ「あなた」「↓」を縦に表示。3D位置を画面へ投影して追従し、回避で文字が回っても表示自体は正立。画角外では隠す。
- 命中時は赤・黄色の48粒が立体的に飛び散る。最大6個の同時バーストを保持し、0.55秒で消える。
- 回避中は水色の3本の螺旋と4つの円環でトルネードを表示。漢字と同じ回転軸で回り、プレイヤー・敵それぞれに追従する。
- 新しい演出は戦闘時間に同期し、一時停止中に進めない。動きを減らす設定では省略。操作表示は維持する。
- 画面離脱時は表示・パーティクル・円環・螺旋のリソースを破棄する。攻撃判定・無敵時間・速度は変更しない。

### X軸トルネードの形状調整

- X軸回避時は中央の円を最大、両端の円を最小とする左右対称の樽形へ変更。5つの円環と螺旋の半径を同じ曲線に合わせる。
- 半径は両端0.7、中央1.5。Y軸回避時は従来の4円環の円錐形を維持する。

## 25. 効果音の強化

- 引き続き外部音源を使わずWeb Audioで合成する。攻撃・回避は抽選／出現音の流用を廃止し、それぞれ専用の音へ変更。
- 命中：下降する低音2層、火花の高域ノイズ、衝撃の低域ノイズ、金属的な高音2層を重ねる。
- 攻撃：高域へ抜ける風切りノイズと上昇音。回避：上昇・下降する風ノイズと音程変化を重ねて竜巻のうねりを表現。
- その他の通知音は三角波主体へ変更し、開始・レア・勝利に高音の重なりを加える。
- 共通出力に75msの短いエコーとコンプレッサーを追加。基本音量0.16、最大同時音源32。調整先は src/data/sound.ts。
- 効果音切・画面切り替え・破棄では、音源とエコーの経路も切断して音を止める。

### 攻撃・回避音の再調整

- 攻撃は上昇する電子音から、1〜2msで立ち上がる鋭い破裂ノイズ・短い低音・細かい破裂の重なりへ変更。
- 回避は音程のうねりから、空気圧の破裂・広帯域の風の噴出・減衰する風の余韻へ変更。高い旋律音は廃止し、短い低音で圧力感を補う。

- 攻撃音をさらに調整：低音層を外し、高域の破裂ノイズと短い高音を強めた大きい「パァン」という音へ変更。回避・命中など他の音は維持。

- 攻撃音をクリティカルヒット風に再調整。高い金属音を複数重ね、短い破裂音を添える「キィン、バシッ」という構成。ダメージやクリティカル判定の追加ではなく音色のみの変更。

- 攻撃命中時の impact に「デュクシ」風の短い2段パルスと歯切れのよいノイズを追加。攻撃開始音とは別に、命中イベント時のみ再生する。

- 命中時の「デュクシ」に、3.4kHz・5.27kHz・7.13kHzの高い金属音を重ねる。最長0.38秒の「キーン」という余韻でクリティカル風の響きを追加。
